# 实现说明（hebang 主题组件库）

> 读者：开发者 / AI 编码助手。
> 目的：说明本仓库已完成的架构、颜色生成规则落地方式、命名约定、验证手段与已知坑。
> 本文与代码同步维护；改颜色规则先改代码，再看是否需要更新本文。
> 最后更新：2026-09-10

## 1. 项目是什么

基于 Element Plus 的企业主题包 + Vue 3 二次封装组件库，pnpm workspace monorepo，发 npm。

```
packages/tokens       @hebang/tokens       设计令牌 + OKLCH 色彩派生引擎（唯一数据源）
packages/theme        @hebang/theme        令牌 → Element Plus 变量的映射层
packages/components   @hebang/components   封装组件（HbButton、HbDialog）
playground            演示应用（private），消费三包 dist 产物，等同真实业务安装
```

三包均为 ESM(`dist/index.js`) + CJS(`dist/index.cjs`) + `.d.ts`/`.d.cts`，`exports` 按 `import`/`require` 分条件带 `types`；vue / element-plus 全部 `peerDependencies` + 构建 `external`。

## 2. 颜色系统 = 三层管线（核心）

```
主色 HEX ──▶ ① 派生引擎(@hebang/tokens) ──▶ ② hb-el 绑定表 ──▶ ③ EP 桥接(@hebang/theme)
   #1F5AA8        oklch.ts + palette.ts        elTokens.ts          index.ts
                   123 个 hb-xxxx 令牌          42 个 hb-el-xxx      44 个 --el-*
```

### ① 派生引擎 —— 规则来源

规则**逐字实现**自《OKLCH 取色与应用规范》（`/Users/yameier/Downloads/e/OKLCH_取色与应用规范.md`）。
注意：该目录里 `src/utils/colorDerivation.ts` 与 `data/palettes.json` 是**旧 HSB 制式**的产物，与文档矛盾，**不要以它们为准**；文档自含全部公式与常量，本仓库以文档为唯一权威。

- `packages/tokens/src/oklch.ts`：HEX⇄sRGB⇄OKLab⇄OKLCH 转换、色域二分裁剪（24 次）、`safeMaxChroma`、`pipe`（L clamp 0.04~0.96 + 色域裁剪）、WCAG 对比度、`textColorOn`（§8 按钮文字黑/白自适应，阈值亮度 0.45）。
- `packages/tokens/src/palette.ts`：`buildHbPalette(brandHex, { mode: 'light'|'dark', neutralType: 'tinted'|'pure' })`
  - 品牌 9 档 tonal 序列（§3.3，锚点=索引 4=输入主色）；secondary +30°/×0.65、tertiary +60°/×0.40
  - 功能色 §3.1 参数表（success H=150 / warning H=60 / danger H=25；色度随品牌饱和度 `ratio=base.C/0.20` 联动；info 完整继承主色）+ container
  - 中性 15 档：light 用规范 L 表；dark 按 §4.2 镜像翻转且末档强制纯黑；色温化（temperFactor 0.35）+ neutralVariant（+15°、sinθ 衰减）；**中性轨不套 pipe 的 L clamp**（否则破坏"纯白/纯黑"语义，代码有注释）
  - 图表 12 档黄金角 137.508°、states（hover L+0.03/C×1.06，active L−0.03/C×0.94；dark ±0.015）、focus/outline/link、§6 语义档位
  - 输出 `named`（123 个 `hb-xxxx` → hex）、`ramps`、`neutral`、`neutralVariant`、`chart`
- 布局类令牌（spacing/radii/fontSize/shadows/componentSizes）仍是静态定义：`packages/tokens/src/layout.ts`。

### ② hb-el 绑定表 —— 业务语义 token

`packages/tokens/src/elTokens.ts`：42 条 `HbElTokenSpec`（bg/bg2/bg3/bg4、border/border2、text/text2/text3、disabled、divider、brand(+light/hover/press)、success/warning/danger 同款四件、white、mask、tag 系列 13 条）。

- token 输出名 = `--hb-el-<表内token原样>`（如 `--hb-el-brand_light`、`--hb-el-tag_lightFill_success_bg_press`）
- 每条分 `light`/`dark` 档；tonal 序列两模式正序索引
- **关键约定**：表把深色中性档定义为倒序编号（依据"bg 深色档 neutral_0（纯黑）"），实现为 `引擎档位[14−i]`；如需改回正序，只动 `resolveHbElRef` 一行
- info 类 tag 按表绑到 **brand 序列**（`--el-color-info` 同源）
- API：`resolveHbElTokens(palette)` → token→hex；`buildHbElCssVars(palette)` → `--hb-el-*`

### ③ EP 桥接 —— theme 包唯一职责

`packages/theme/src/index.ts`：`buildElementPlusVars(elTokens, named)` 把绑定结果写入 44 个 `--el-*`（text←text/text2/text3/disabled，bg/fill←bg 系列，border←border2/border/divider，mask/white←固定值，功能色四件←表档位；表未覆盖的 `primary-light-3/5/7/8` 直取 tonal 档位并有注释）。

`buildThemeVars(brandHex, {mode})` = `--hb-space-*` + `--hb-*`(123) + `--hb-el-*`(42) + `--el-*`(44) ≈ **223 变量/模式**。`applyTheme(vars)` 运行时写到 `<html>`（内联优先级最高，永远压过静态主题）。

静态 CSS：`packages/theme/scripts/generate-css.mjs` 在构建期把默认主色的 light/dark 两套写进 `dist/index.css`（`:root` + `html.dark`）。**深色模式需业务方同时挂 `html.dark` class + 引入 `element-plus/theme-chalk/dark/css-vars.css`**。

### SCSS 输出（与 JS 同源生成，勿手改 dist）

- `@hebang/tokens/scss/variables` → `$hb-xxxx` + `$hb-el-xxxx`（light）
- `@hebang/tokens/scss/palette-dark` → 深色对照
- `@hebang/theme/scss/variables` → 引擎变量 + EP 官方 SCSS 链路别名（`$hb-color-primary` 等）
- `@hebang/theme/scss/element-plus` → 进阶：配合 EP 源码重编译 theme-chalk

## 4. playground 结构（`playground/src/App.vue`）

色板（`el-color-picker`）+ Light/Dark 单选驱动 `buildThemeVars → applyTheme`；页面 chrome 直接消费 `var(--hb-el-*)`。区块：取色输入、§8 对比度自检卡、**42 行 hb-el 绑定表（五列：token｜中文｜浅色档｜深色档｜生效中）**、5×9 tonal 序列、辅助品牌/状态色、中性 15 档双轨 + 语义表、图表 12 档、封装组件示例（HbButton、HbDialog 异步提交）。

绑定表联动语义（实时计算，非快照）：
- 浅色/深色两列由 `resolveHbElTokens(buildHbPalette(currentHex, {mode:'light'|'dark'}))` 派生——**色板选色时两列同步重算**（如换品牌色后 `success_*` 因 §3.1 语义色度公式跟随基色饱和度联动，中性档 hex 基本稳定）；
- 「生效中」列 = `resolveHbElTokens(palette)`（当前模式的实际 CSS 写入值），**Light/Dark 切换只翻转该列**，表头同步标注 `生效中 · light/dark`，当前模式对应的档位列高亮；
- 状态模型 `currentHex = preview ?? committed ?? 默认蓝`：点预设/拖面板经 `@active-change` 进 `preview`；`committed` 变更（确定/清空）才用提交值接管；**切模式不清 preview**（否则未提交的选色会被重置回默认蓝，已修复并有注释）。

⚠️ el-color-picker 使用坑（已在代码注释）：EP 2.14 的 modelValue 是**延迟提交**（点预设/拖面板不改 v-model，点"确定"才发），实时换肤必须用 `@active-change`；本仓库双通道：active-change 实时预览 + v-model 提交持久化。

## 5. 新增组件约定（components）

- `src/components/HbXxx/HbXxx.vue`，props 类型集中放 `src/types.ts`（避免从 .vue 再导出类型）
- `defineOptions({ name: 'HbXxx' })`；`src/index.ts` 具名导出 + `install` 全量注册
- 样式只引用 `var(--el-*)` / `var(--hb-*)`，**禁止硬编码颜色**；悬停/点击态可用 `--hb-el-brand_hover/press`
- 业务自定义色值一律走 `hb-el` 层命名：新增 token 加到 `HB_EL_TOKENS`，禁止散落裸 hex

## 7. 已知坑与决策记录

1. **`npm pack` 不改写 `workspace:*`**（会把 `workspace:*` 原样打进依赖声明，业务方安装报错）→ 打包/发布一律用 pnpm；内部依赖声明用 `workspace:^`。
2. **type:module 双格式包的 types 拆分**：`exports` 的 import/require 条件各挂各的 `types`；CJS 侧 `dist/index.d.cts` 由 `scripts/copy-cjs-types.mjs` 构建期复制生成（publint 规则驱动）。
3. **d.ts 内相对引用无扩展名会让 node16 解析报错** → tokens/theme/components 的 vite-plugin-dts 均开 `rollupTypes: true`，类型收敛单文件。
4. **中性轨 L=1.0/0 不能过 pipe 的 L clamp**（见 §2-①）。
5. **运行时换肤永远压过静态主题**：内联 style > `:root` 样式表；EP 自身 `#409eff` → theme 覆盖 → applyTheme 内联，三层顺序固定。
6. **未实现（待设计确认）**：§8"按钮文字黑/白自适应"仅以 `textColorOn()` 提供并在页面展示，未注入 EP 组件级 `--el-button-text-color`；若品牌色会偏亮（黄/绿系）需补这一步。
7. **绑定表数据问题（已忠实呈现未擅改）**：dark 模式 `border2`（neutral_4→#1a1d20）对 `bg2`（neutral_2→#121416）对比约 1.3:1，低于 §8 描边 ≥3:1，页面自检卡会标红；需要设计侧决定是否调档。
